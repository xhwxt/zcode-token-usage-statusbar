# 使用说明

面向已经装好插件的人：设置窗怎么开、每一项改什么、什么时候需要补注入。
安装步骤见 [README.zh-CN.md](../README.zh-CN.md)，性能与实测数据见 [PERF.md](PERF.md)。

---

## 1. 三个入口

| 入口 | 位置 | 用来做什么 |
|---|---|---|
| 状态条 | ZCode 对话窗口最底部 | 看当前会话的用量；悬停看明细 |
| ⚙ 齿轮面板 | 状态条右端 | 开关条面显示项、切语言、快速看归档状态 |
| 完整设置窗 | 齿轮面板底部「打开完整设置…」 | 改刷新频率、归档阈值、上下文兜底、诊断 |

齿轮面板只放高频项，改完即时生效；完整设置窗是独立窗口（730×780），
改完点「保存」后约 1 秒生效——它写的是 `config.json`，主进程会立刻重读并重推一次快照。

> 完整设置窗需要主进程支持（v64 起）。如果按钮点了没反应或提示「主进程无响应」，
> 说明客户端还在跑旧版注入，重启 ZCode 即可。

## 2. 条面各项

| 项 | 显示内容 | 悬停明细 |
|---|---|---|
| 生成速度 | 最近一次完成请求的输出 tokens ÷ 生成耗时 | — |
| 上下文 | 微进度条 + 占比，颜色随占比变化 | 窗口大小来源 |
| 本轮 | 本轮 tokens / 请求次数 / 耗时 / 首字延迟 | 输入 / 输出 / 缓存命中 / 缓存写入 / 思考拆分 |
| 会话累计 | 当前会话总 tokens | 同上五项拆分 + 代码变更行数 |
| 工具调用 | 当前会话工具调用次数，错误时右侧红标 | 各工具调用次数、耗时、错误 |
| 今日合计 | 今天所有会话的 tokens | — |
| 子代理 | 后台子代理消耗，运行中显示蓝色圆点 | 点击打开固定明细面板 |

每个对话窗口只显示自己的数据。数据来自本地 SQLite 的只读查询，
请求完成后才落库，所以数字反映的是「最近一次已完成请求」。

条面颜色：生成速度 ≥70 绿、40–70 黄、<40 红；上下文占比在大窗口下 40%/60% 预警，
其余窗口 70%/85% 预警，超限时亮红闪烁并弹出处置建议。

## 3. 完整设置窗逐项说明

### 01 刷新与采集

| 项 | 默认 | 说明 |
|---|---|---|
| 活动期最小间隔 | 1500 ms | 检测到数据库写入后的最快刷新节奏。下限 300 ms。调大更省 CPU，但连续发消息时数字会更「跳」。 |
| 兜底心跳 | 30000 ms | 空闲时定期检查一次，防止文件监听事件丢失。下限 10000 ms。 |
| 常驻查询进程 | 开 | 复用同一个 Python 进程，省掉每次查询的解释器启动开销（约 60–100 ms）。关掉会回退到一次性短进程，一般不需要关。 |

数据是**事件驱动**的：`fs.watch` 监听数据库写入，去抖后查询并推送；没有写入就不查。
所以空闲时几乎零开销，上面的间隔只在真正有活动时才起作用。

### 02 旧会话归档

| 项 | 默认 | 说明 |
|---|---|---|
| 归档阈值 | 7 天 | 超过这么多天未活动的会话算「旧」。`0` = 关闭。 |
| 处理方式 | `skip` | 见下表。 |

三种处理方式的实际差别：

| 模式 | 旧会话进候选池 | 省查询 | 界面上看到 |
|---|---|---|---|
| `off` | 是 | 否 | 无提示 |
| `count` | 是 | 否 | 「N / M 个会话超过 X 天未活动（仅统计）」 |
| `skip` | **否** | **是** | 同上，并注明其中多少个不加载 |

判定依据是每个会话自己的最后完成请求时间，**正在用的会话永远不会被误标**；
当前窗口的焦点会话和最新会话无条件保留。

用 `skip` 时，1 天阈值下本机候选池从 12 个会话降到 2 个，省掉每个会话的聚合查询。
`count` 只是把数字报出来，不改变加载行为——如果你以为它在「折叠侧栏」，说明一下：
**插件改不了 ZCode 自己的侧栏**，这里说的「不加载」指的是不进插件的候选池。

统计数字是全库口径（本机 76 个会话，7 天阈值下 51 个旧会话），不是拿 12 个候选
会话当分母——那样永远算不出有意义的结果。

### 03 显示

| 项 | 默认 | 说明 |
|---|---|---|
| 语言 | 中文 | 中文 / English。**这里改完，状态条会一起切换**——语言以 `config.json` 为准随快照下发，齿轮面板里切换时也会写回配置，两处不会再各说各话。 |
| 上下文窗口覆盖 | 留空 | 留空 = 自动：优先读 ZCode 原生 UI（服务端下发、跟随模型）→ 模型目录查表 → 配置兜底。只有自动识别失败时才需要手动填。 |

### 04 高级

| 项 | 默认 | 说明 |
|---|---|---|
| 热更新 | 开 | `overlay.js` 改动后免重启自动重载。调试用，平时开着也无妨。 |
| 诊断落盘 | 关 | 每约 15 次推送把一个窗口的 `__zusageDiag` 写成 `diag-<n>.json`。**排障时才开**，开着会持续产生 IPC + 同步磁盘 IO。 |
| Python 路径 | 只读 | 安装时探测的结果。要改请直接编辑 `config.json` 的 `python_path`。 |
| 运行时目录 | 只读 | 注入文件所在的数据目录。 |

保存走「读现有配置 → 合并白名单字段 → 写临时文件 → 原子替换」，不会把
`config.json` 写坏，也不会动 `python_path` / `asar_path` 这些不归界面管的字段。
整数字段有钳制：间隔类低于下限会被抬到下限，归档天数限制在 0–3650。

## 4. 配置文件的优先级

`config.json` 是唯一的配置来源，界面只是它的编辑器。位置：

- 标准安装：`~/.zcode/zcode-token-usage-statusbar/config.json`
- `--dev` 安装：仓库目录下的 `config.json`

手改文件同样生效（改完约 1 秒主进程重读）。字段含义见
[README.zh-CN.md 的配置一节](../README.zh-CN.md#配置configjson)，
完整模板见 [config.example.json](../config.example.json)。

不认识或不合法的字段会被忽略，不会让插件起不来；取值越界会被钳到合法范围。

## 5. 什么时候需要手动干预

### ZCode 升级之后

官方升级会整包覆盖 `app.asar`，注入行随之消失——表现为状态条不见了。

```bash
python autopatch.py check   # 0=已注入 / 1=需要补 / 2=找不到 ZCode
python autopatch.py apply   # 需要时补注入（静默，不弹监控窗口）
```

`check` 只解析 asar 头部（实测 74–99 ms），适合放进登录时的计划任务；
`apply` 只在检查失败时才重打包（307 MB，十几秒）。

做不到「真正的零维护」：打包版 Electron 会拒绝 `NODE_OPTIONS`
（"Most NODE_OPTIONs are not supported in packaged apps"），启动器/包装器方案
又会被 electron-updater 重建快捷方式冲掉。所以这里给的是「升级后跑一条命令」。

### 状态条不出现

按顺序排查：

1. 重启 ZCode。`inject-main.cjs` 和 `overlay.js` 的改动都需要重启才生效
   （只有 `overlay.js` 支持热更新）。
2. 跑 `python autopatch.py check`，看注入是否还在。
3. 打开设置窗的「高级」，确认 Python 路径指向一个真实存在的解释器。
4. 打开「诊断落盘」，重启，看数据目录里的 `diag-*.json`。

### 数字不对 / 一直是 0

- 请求完成才落库，正在生成的请求不计入。
- 新会话还没产生已完成请求时，条面会是零值并带来源提示。
- 会话迁移过工作区的话，历史用量会一并算进新目录（`model_usage` 没有工作区维度）。

### 想回到默认配置

删掉或改名 `config.json`，重启 ZCode，会按默认值重新生成。

## 6. 卸载

```bash
python install.py --remove    # 剥离注入 + 移除 MCP 注册与 /usage 命令 + 删除数据目录
# 或只卸状态条：python patch_install.py remove
```

卸载不依赖备份：只增删本工具自己的注入行（运行中也可执行，重启后生效），
不会把官方升级后的新版 asar 还原回旧版本，也不影响其它工具后装的注入行。
